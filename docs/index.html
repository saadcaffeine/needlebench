About NeedleBench what it is, how it works, related tools

What it is

A local, browser-based workbench for ESP32-S3 boards running Needle 2, Cactus Compute's 45M-parameter tool-calling model, ported to the chip by needle-2-esp32. You type a request; the model, running entirely on the microcontroller, answers with a JSON tool call that drives the on-board NeoPixel. Nothing is sent to a server. The page talks straight to the board over USB.

How it works

  1. Web Serial. Chrome or Edge opens the board's USB-UART bridge directly. Web Serial only works on secure origins, so the page is served over HTTPS (GitHub Pages) or from localhost.
  2. Line protocol. The firmware prints one message per line. EVT lines report status, TOK streams one token, CONF gives groundedness and ACT reports what the hardware did. The LINK, BOARD, TX and RX lights show this traffic.
  3. Inference. The 13.1 MB model is memory-mapped from its own flash partition and the KV cache lives in octal PSRAM. The tool schema is primed once per boot (about 52 s). After that each token takes about 0.55 s across both cores.
  4. Grammar-constrained decoding. Every reply is a call that matches the schema compiled into the firmware, or the empty call []. The model is a dispatcher, not a chatbot.
  5. Flashing. Uses Espressif's esptool-js 0.6.1, bundled locally so it works offline. Every image is verified by MD5 against the flash after writing.

Board requirements

ESP32-S3 with 16 MB flash and 8 MB octal PSRAM (an "N16R8" module), a WS2812 NeoPixel on GPIO48, and the console on the UART bridge port, not the native USB port.
